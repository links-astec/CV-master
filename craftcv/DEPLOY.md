# Deploying CVMaster

```
Vercel   →  Frontend (Vite build)            https://cvmaster.live
Render   →  API (Express + Puppeteer)        https://api.cvmaster.live
Neon     →  PostgreSQL database
```

The frontend calls the API at `VITE_API_URL` (set in `vercel.json`). The auth cookie is
set on `.cvmaster.live`, so both sites must stay on that domain.

> **Why Neon?** Render's free Postgres expires 30 days after creation and is then deleted.
> Neon's free tier doesn't expire. Any Postgres works — only `DATABASE_URL` changes.

---

## 1. Create the database (Neon)

1. Sign up at https://neon.tech → **New Project**, region **AWS Europe (Frankfurt)** (closest to the Render API).
2. Copy the connection string from the dashboard. It looks like
   `postgresql://user:pass@ep-xxxx.eu-central-1.aws.neon.tech/neondb?sslmode=require`.
3. Create the tables from your machine:
   ```bash
   # in craftcv/.env
   DATABASE_URL=postgresql://...neon...?sslmode=require
   ADMIN_EMAIL=you@example.com
   ADMIN_PASSWORD=a-strong-password

   npm run db:migrate
   ```
   You should see `✓ Schema migrations complete.` and the admin account being created.
   Migrations are safe to re-run; Render also runs them on every deploy.

## 2. Point the API at it (Render)

1. Render dashboard → **craftcv-api** → **Environment**.
2. Set `DATABASE_URL` to the Neon connection string → **Save** (Render redeploys).
3. Check https://api.cvmaster.live/api/health — it should say `"db": true`.

Other variables to set on Render:

| Variable | Notes |
|---|---|
| `JWT_SECRET`, `ADMIN_JWT_SECRET` | Generated by `render.yaml`. If missing, the server uses a random secret and everyone is logged out on each restart. |
| `GROQ_API_KEY` | AI features |
| `STRIPE_SECRET_KEY` | Required to take payments. Without it, exports are **unavailable** in production (set `ALLOW_FREE_EXPORTS=true` to make them free instead). |
| `STRIPE_WEBHOOK_SECRET` | See step 4 |
| `RESEND_API_KEY` | Sends every email (CVs, password resets) — see step 6 |
| `RESEND_FROM` | Optional, defaults to `CVMaster <noreply@cvmaster.live>`. Must be on the verified domain. |
| `GROQ_MODEL` | Optional, defaults to `openai/gpt-oss-120b` |
| `SMTP_*` | Optional fallback. Render's free tier blocks SMTP, so this only helps locally. |
| `GOOGLE_CLIENT_ID` | Google sign-in |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | Only used when the first admin is created |

## 3. Frontend (Vercel)

`vercel.json` already sets `VITE_API_URL=https://api.cvmaster.live`. Also set
`VITE_GOOGLE_CLIENT_ID` in Vercel → Settings → Environment Variables (needed at build time).

## 4. Stripe webhook

Stripe dashboard → Developers → Webhooks → **Add endpoint**:

- URL: `https://api.cvmaster.live/api/webhooks/stripe`
- Events: `checkout.session.completed`, `payment_intent.succeeded`

Copy the signing secret into `STRIPE_WEBHOOK_SECRET` on Render. The webhook is a backup:
payments are also verified directly with Stripe when the user returns from checkout.

## 5. Google OAuth

Google Cloud Console → APIs & Services → Credentials → your OAuth client → add
`https://cvmaster.live`, `https://www.cvmaster.live` and `http://localhost:5173` to
**Authorized JavaScript origins**.

---

## 6. Email (Resend) — required for emailed CVs and password resets

Render's free tier blocks outgoing SMTP, so Gmail cannot send from the live server.
Email goes through Resend's HTTPS API, which only sends from a domain you have verified.

1. https://resend.com → **Domains → Add domain** → `cvmaster.live` (region: EU).
2. Resend shows DNS records (an MX and TXT records for SPF, and a TXT record for DKIM).
   Add them exactly as shown at your domain registrar's DNS settings.
3. Click **Verify** in Resend. It usually takes a few minutes (can take up to 48 h).
4. **API Keys → Create API key** (Sending access) → put it in `RESEND_API_KEY` on Render.
5. If `SMTP_FROM` is set to a gmail.com address on Render, remove it — it is no longer used.
6. Test: sign in on the live site and export a CV, or call `GET /api/email-test` while signed in.

The health check shows `"email": true` once a mail provider is configured.

## Local development

```bash
cp .env.example .env     # fill in DATABASE_URL (a separate Neon branch is ideal) and keys
npm install
npm run db:migrate
npm run dev              # Vite :5173 + Express :3001
```

## Backups

Neon keeps point-in-time history on its free tier for a short window. For your own copy:

```bash
pg_dump "$DATABASE_URL" > backup-$(date +%F).sql
```
